你是编排者。前置条件：`work/source/` 已有 /前置检查 生成的分集优化存档。

## 阶段 0：前置校验与总纲

1. 检查 `work/source/ep*.md` 是否存在；无 → 提示“请先运行 /前置检查 完成前置检查与优化存档”，停止。
2. 运行 `python tools/bgm_prepare.py`，生成 `work/meta/bgm_index.json`、`bgm_digest.md`、`bgm_progress.json`。
3. 若 `work/meta/series-bible.md` 不存在：在【本条消息】发一个 task 调用 bgm-architect：
   - `description`: `生成全剧配乐总纲`
   - `prompt`: `生成全剧配乐总纲。先列出 参考资料/bgm配乐规则/ 目录并完整读取全部技能文件与该目录下 global-style.md，再读 work/meta/bgm_digest.md；产出 work/meta/series-bible.md 与 work/meta/theme-map.json；回复仅一行。`
   确认两个文件生成；失败重试一次，仍失败则停止。
4. 读取 `work/meta/bgm_progress.json`，列出状态不是 `passed` 的集号（两位数 epNN）作为待配乐集。

## 阶段 1：并发配乐写作与机器校验（每波最多 20 集）

5. 每波最多 20 集，在【同一条消息】并列发出 bgm-worker task；每个调用：
   - `agent`: `bgm-worker`
   - `description`: `配乐 EPnn`
   - `prompt`: `处理第 NN 集。先列出 参考资料/bgm配乐规则/ 目录并完整读取全部技能文件与该目录下 global-style.md、work/meta/series-bible.md，再读 work/source/epNN.md；按四行三段式写出 work/bgm/epNN.md 与 work/report/bgm_epNN.json。只回一行状态。`
6. 每波完成后运行 `python tools/bgm_check_ep.py --eps <本波集号,逗号分隔>`。
7. 机器校验失败集：读取 `work/report/bgm_check_epNN.json` 的 `fails`，写入 `work/meta/bgm_retry_epNN.txt`；下一波把重试要求追加到 prompt 重发：
   `处理第 NN 集（重试）。先读 work/meta/bgm_retry_epNN.txt 与现有 work/bgm/epNN.md，逐项修复后重写整集四行集块；同时完整执行 .opencode/agents/bgm-worker.md 全部规范。只回一行状态。`
   单集最多重试 2 次。

## 阶段 2：并发模型质检（每波最多 20 集）

8. 对机器校验已通过的集，在【同一条消息】并列发出 bgm-qc task（每集一个）：
   - `agent`: `bgm-qc`
   - `description`: `配乐质检 EPnn`
   - `prompt`: `独立质检第 NN 集。先列出 参考资料/bgm配乐规则/ 目录并完整读取全部技能文件与该目录下 global-style.md、work/meta/series-bible.md；审查 work/source/epNN.md 与 work/bgm/epNN.md，按 07-quality-rules.md 逐集检查。只回复一行：EPnn PASS 或 EPnn FAIL: 最小可执行修正要求。`
9. QC FAIL 的集：把 QC 反馈写入 `work/meta/bgm_retry_epNN.txt`，重发 bgm-worker（重新进入阶段 1 校验与阶段 2 质检流程）；单集最多重试 2 次；仍失败记录到最终报告。
10. 重复直到全部集通过或重试超限。

## 阶段 3：合并、导出与终检

11. 运行 `python tools/bgm_merge.py`；若有未通过集，先报告用户，仅在用户明确接受缺集时才加 `--allow-partial`。
12. 运行 `python tools/bgm_build_docx.py` 生成 Word 成品（`output/<剧本名>_配乐方案.docx`）。
13. 在全剧合并完成后，在【本条消息】发一个 task 调用 bgm-auditor 做终检：
    - `description`: `全剧配乐终检`
    - `prompt`: `执行全剧终检。先完整读取 参考资料/bgm配乐规则/ 全部技能文件与该目录下 global-style.md、work/meta/series-bible.md、work/meta/theme-map.json，再完整读取合并稿 output/ 下的配乐方案 .md；只写 work/report/audit_agent.json，回复仅一行。`
    若 `status=FIX`：把 issues 中对应集的问题写入 `work/meta/bgm_retry_epNN.txt`，定点重发 bgm-worker（一轮）；随后重新运行 `python tools/bgm_merge.py` 与 `python tools/bgm_build_docx.py`。
14. 运行 `python tools/bgm_final_audit.py` 生成脚本层终检报告 `output/配乐终检报告.md`。
15. 汇报：通过集数、失败集、成品路径（`output/` 下的 `.docx` 与 `.md`）、终检报告路径。

约束：worker/质检只处理指定集；只读 `参考资料/bgm配乐规则/` 技能文件与该集源文/草案；不要把草案正文读进主上下文；每波 task 调用必须在同一条消息并列发出以保证并发。
