你是编排者。前置条件：`work/source/` 已有 `/前置检查` 生成的分集优化存档，且 `work/meta/source_dialogue.tsv` 已冻结。

本命令**直接输出目标 A/B 风格的竖屏分镜稿**；旧“导演执行稿”模式停用。默认 profile `B_bilingual_full`；切 A 请改 `storyboard-profile.json` 的 `active`。

## 阶段 0：前置校验与准备

1. 检查 `work/source/ep*.md`、`work/meta/source_dialogue.tsv`、`work/meta/ep_index.json` 是否存在；缺失则提示先运行 `/前置检查`，停止。
2. 读取 `storyboard-profile.json`，确认 `active` profile 与时间/字段/语言策略。
3. 运行 `New-Item -ItemType Directory -Force work/storyboard,work/report`。
4. 读取 `work/meta/ep_index.json` 得到全部集号（两位数 epNN）。
   - 试跑：若用户明确指定集（如“先做第1集”），只对该集发 planner/writer，其余集跳过；正式运行再全量。

## 阶段 1：分镜计划（每波最多 20 集）

5. 每波最多 20 集，在【同一条消息】并列发出 storyboard-planner task：
   - `agent`: `storyboard-planner`
   - `description`: `分镜计划 EPnn`
   - `prompt`: `处理第 NN 集。先完整读取 storyboard-profile.json、参考资料/分镜细则/ 全部文件、work/source/epNN.md、work/meta/source_dialogue.tsv（按本集过滤）、work/meta/facts_lock.md、work/meta/handoff.json 与 work/preflight/optimized/epNN.json（若存在），按 01-planning.md 输出 work/storyboard/epNN_plan.json。单镜≤4s、组≤15s、集≤150s（150s 是上限不是目标）；每集 6—12 组、28—50 镜、4500—7000 中文字；短集按真实内容写短，不得为凑时长加镜/加动作；每组完整空间起点；台词逐字保留、可拆不可改；禁止 △/SPECTACLE/[EN]:。只回一行状态。`
6. 每波后检查 `work/storyboard/epNN_plan.json` 是否齐全；缺失或失败的重发一次；仍失败则报告并停止。
7. 全部计划完成后运行 `python tools/storyboard_check.py --plans work/storyboard` 校验计划的时间/组/镜/空间起点；不合格的定点重发 planner。

## 阶段 2：写稿与硬校验（每波最多 20 集）

8. 每波最多 20 集，在【同一条消息】并列发出 storyboard-writer task：
   - `agent`: `storyboard-writer`
   - `description`: `分镜写稿 EPnn`
   - `prompt`: `处理第 NN 集。先读 work/storyboard/epNN_plan.json、参考资料/分镜细则/00-contract.md 与 02-craft.md、work/source/epNN.md、storyboard-profile.json；若是重试，再读 work/storyboard/retry_epNN.txt 与现有 work/storyboard/epNN.md，逐项修复。严格按计划写 work/storyboard/epNN.md；不得改时间/组号/镜号/台词；不得为凑时长/字数扩写；不得出现 △/SPECTACLE/[EN]:/【人物站位】/【景别。只回一行状态。`
9. 每波完成后运行：
   ```powershell
   python tools/storyboard_check.py --dir work/storyboard --eps <本波集号,逗号分隔>
   ```
   读取 `work/report/storyboard_check.json` 的 `fails`：
   - 组数/镜头数/字数超目标 → **重发 planner** 压缩计划（合并重复反应/无功能镜头，删修饰，不删台词）；计划通过后重发 writer；
   - 字段/时间轴/空间起点/台词标签问题 → 重发 writer；
   具体失败原因写入 `work/storyboard/retry_epNN.txt`，下一波带原因重发；单集最多重试 2 次。
10. 重试超限集：保留产物并在最终报告中单列；不得静默跳过。

## 阶段 3：合并、导出与对账

11. 运行 `python tools/storyboard_merge.py`（有缺集时先报告；仅在用户明确接受缺集时才加 `--allow-partial`）。
12. 运行 `python tools/storyboard_build_docx.py`，生成 `output/<剧本名>_竖屏分镜稿.docx`。
13. 若 `work/meta/source_dialogue.tsv` 存在，运行 `python tools/audit_dialogue.py --dir work/storyboard`，把结果写入 `work/report/dialogue_audit.json`；台词/标签失败只报告、不阻断，最终写入质检/交付说明。
14. 运行 `python tools/storyboard_check.py --dir work/storyboard` 做全量终检；失败集列入报告。

## 阶段 4：汇总

15. 最终报告必须包含：
    - 使用 profile、集数；
    - 每集组数/镜头数/时长/中文字数；
    - 硬校验通过/失败集号与失败原因；
    - 台词对账失败/补标-需确认行数（若有）；
    - 成品路径：`output/<剧本名>_竖屏分镜稿.md` 与 `.docx`；
    - 与目标稿的差异说明（若有）。

约束：不要把分镜正文读进主上下文；不要修改 `参考资料/`；worker 只回一行状态；每波 task 必须在同一条消息并列发出；计划与写稿都不得改台词、剧情、人物关系或结果。
