你是编排者。前置条件：`work/source/` 已有 /前置检查 生成的分集优化存档。

## 阶段 0：前置校验

1. 检查 `work/source/ep*.md` 是否存在；无 → 提示“请先运行 /前置检查 完成前置检查与优化存档”，停止。
2. 若 `work/meta/ep_index.json` 或 `work/meta/progress.json` 缺失，运行 `python tools/assemble_source.py --rebuild` 从现有 `work/source` 重建索引与进度。
3. 读取 `work/meta/progress.json`：
   - `blocked` 集：前置质检判定主角覆盖不足，**本阶段不再判断、不重新计算主角覆盖**；直接从待炼集排除并在会话中列出。
   - 若 `progress.json` 丢失或被重建，读取 `work/preflight/protagonist.json` 的 `blocked_eps`，同样视为 blocked；不重新计算。
   - 其余状态不是 `passed` / `passed-with-issues` 的集号（两位数 epNN）作为待炼集；全部已通过则跳到阶段 2。
   - 若待炼集为空且存在 `blocked` 集：只报告 blocked 清单与原因并停止，不生成空成品。
   - 不在本阶段运行 `preflight_protagonist_check.py`；`blocked` 只来自前置阶段，已进入炼本的集不回判。

## 阶段 1：并发炼稿与校验（每波最多 20 集）

4. 每波最多 20 集，在【同一条消息】并列发出 director task；每个调用：
   - `agent`: `director`
   - `description`: `炼稿 EPnn`
   - `prompt`: `处理第 NN 集。先完整读取 .opencode/agents/director.md 并严格执行其中全部规范（含必读文件清单，以及“每句台词括号内必须填写可表演的细致情绪或神态”硬规则；括号提示须含声音/气息/情绪状态 + 至少一个可拍的面部、眼部、下颌、喉部或手部细节，情绪落点句 2—3 个可见细节；连续动作与姿态余波写入 △，不得把动作段塞进括号；镜头块内不写具体秒数；文化背景以 SOURCE 为唯一依据，不得添加 SOURCE 未建立的中式元素/背景/器物/礼仪/称谓，不得从“夹/端/递”等中文动词反推筷子、筷架等器物）。先按 参考资料/炼本细则/protagonist-shot-design.md 完成主角镜头规划（单主角，自动识别，不设双主角）：把 shots 写入 work/report/epNN.json 的 shot_plan，再写正文；主角关联镜不低于 70%，主角本人镜不低于 35%，纯 N 镜不超过 30%，配角互动连续不超过 2 镜；有主角在场的场次至少 1 个 P/R；不得用主角站背景凑数。完成 work/draft/epNN.md、work/report/epNN.json、work/report/epNN_production_notes.md 写盘。只回一行状态。`
5. 每波完成后运行 `python tools/check_ep.py --eps <本波集号,逗号分隔>`。
6. 校验 FAILED 的集：读取 `work/report/check_epNN.json` 的失败原因，写入 `work/meta/retry_epNN.txt`；下一波把重试要求追加到 prompt 重发：
   `处理第 NN 集（重试）。先读 work/meta/retry_epNN.txt、work/report/check_epNN.json 的 protagonist_* 项与现有 work/draft/epNN.md，逐项修复其中列出的全部问题；先重做 shot_plan 再重写整集；同时完整执行 .opencode/agents/director.md 全部规范。只回一行状态。`
   单集最多重试 2 次。不得跳过校验。
7. 重试超限集：运行 `python tools/check_ep.py --eps <集号> --allow-issue-pass` 降级通过（自动生成 `work/report/epNN_issue.md`，进度标记 `passed-with-issues`）。
8. 重复直到全部集通过（`passed` 或 `passed-with-issues`）。

## 阶段 2：合并、回写与终检

9. 运行 `python tools/merge.py`（全部通过时无需 `--allow-partial`；存在 `blocked` 集时追加 `--allow-partial`，生成部分成品）。
10. 运行 `python tools/writeback_docx.py`（回写成品 docx，保留源文档排版；输出锁定错误提示关闭 Word/WPS 后重跑；存在 `blocked` 集时追加 `--allow-partial`）。blocked 集不替换，保留源 docx 原文。
11. 运行 `python tools/final_audit.py`（存在 `blocked` 集时追加 `--allow-partial`）。
12. 运行 `python tools/generate_summary.py`（生成 `work/report/production_summary.md` 总修改优化说明）。
13. 运行 `python tools/generate_qc_report.py`，生成 `output/<剧本名>_质检报告.md` 与 `.docx`：报告有无较大剧情修改（逻辑修复明细、场景统一、动作丰富统计）、各集在全部阶段（前置/炼本）的台词变动核查结果，以及动作/对白密度检测与处理记录（△/台词比、最长 △ 段、最长连续对白段、△ 检测与对白检测命中、合并前→后 △ 条数与 △ 合并明细）。
14. 最终报告必须包含：通过 / 降级通过 / 未通过 / blocked 集号；blocked 集的原因（来自 `work/preflight/protagonist.json`）与“未进入炼本”说明；成品 Markdown 与 docx 路径（`output/`）；质检报告路径（`output/<剧本名>_质检报告.md/.docx`）；总修改优化说明路径（`work/report/production_summary.md`）；各集制作说明路径列表（`work/report/epNN_production_notes.md`）；若有 `passed-with-issues` 集则单独列出并附对应 `epNN_issue.md` 路径。

约束：不要把 draft 正文读进主上下文；不要修改 `参考资料/`；worker 只回一行状态；每波 task 调用必须在同一条消息并列发出以保证并发。`blocked` 只来自前置质检，不在炼本阶段重新判定主角覆盖；已进入炼本的集不回判。
