你是编排者。本命令完成「前置检查与优化存档」：识别输入 → 抽取 → 全本质检 → 词数检测 → △/对白密度检查 →〔用户授权后〕合并连续 △ → 逐集修复优化＋格式标准化（合并执行）→ 回写与直接存档（脚本）→ 台词锁定校验 → 全剧分析。完成后停止，不进入炼本。

## 阶段 0：输入识别与准备

1. 列出 `剧本输入/` 目录中的 `.docx` 文件（忽略 `~$` 开头的临时文件）。
   - 0 个：报告“请把剧本 word 放入 `剧本输入/` 文件夹后重新运行 /前置检查”，停止。
   - 1 个：使用它，继续。
   - 多个：使用 question 工具让用户选择本次处理的文件（custom: false），报告其余文件需移出后重试。
2. 若 `work/source`、`work/preflight`、`work/draft`、`work/bgm` 任一存在，运行 `python tools/archive_work.py` 归档旧产物。
3. 运行 `python tools/split_docx.py --extract-only`，得到 `work/meta/paragraphs.txt`（源段落清单）。
4. 运行 `New-Item -ItemType Directory -Force work/preflight,work/preflight/optimized`。

## 阶段 1：全本前置质检、词数检测与 △ 节奏检查

5. 在【本条消息】发一个 task 调用 preflight-reviewer：
   - `description`: `剧本前置质检`
   - `prompt`: `完整执行 .opencode/agents/preflight-reviewer.md，审查工作区当前剧本，写出 work/preflight/report.md、work/preflight/report.json，并只回一行状态。`
6. 确认 `work/preflight/report.json` 与 `report.md` 均已生成；缺失则重试一次；仍失败则报告用户并停止。
7. 运行词数检测（分两步）：
   ```powershell
   python tools/preflight_spoken_check.py
   $spoken_exit = $LASTEXITCODE
   if ($spoken_exit -gt 1) { exit $spoken_exit }
   ```
   然后读取 `work/preflight/spoken_words.json`，把所有 `status=FAIL` 的集用表格“集数｜英文有声台词总词数｜不合格原因”输出到当前会话。150 和 300 均为合格边界；词数不合格只报告，不影响后续流程，也不得通过增删改台词来凑数。
8. 运行 △/对白 密度与节奏检查（双向信息项，与词数检测同级，不阻断）：
   ```powershell
   python tools/preflight_atom_check.py
   $atom_exit = $LASTEXITCODE
   if ($atom_exit -gt 1) { exit $atom_exit }
   ```
   - 读取 `work/preflight/atom_pacing.json`，把所有 `status=RISK` 的集用表格“集数｜△数｜有声台词行｜△/台词比｜最长无台词△段｜近似△对｜原因”输出到当前会话。△ 过多只报告、不作为错误；优化方式为「合并」：把连续 △ 段合并为 1 条或少量完整 △，完整保留全部事实与表演动作，只减少 △ 条数（不删减内容）。
   - 读取 `work/preflight/dialogue_density.json`，把所有 `status=RISK` 的集用表格“集数｜△数｜有声台词行｜△/台词比｜最长连续对白段｜原因”输出到当前会话。**对白过多/动作不足只检测与报告**，不作为错误、不影响是否进入炼本；本阶段不补写动作，不增删改台词或 △。
9. 向用户展示：评级、必须修改数量、疑似问题数量、最需处理的 3—5 项、词数不合格集清单、△ 节奏风险集清单、对白密集/动作不足集清单。

## 阶段 2：△ 冗余合并授权（可选）＋逐集修复优化＋格式标准化（每波最多 20 集并发）

10. 若阶段 1 存在 `status=RISK` 的集，用 question 工具征询用户是否合并连续 △（信息项、非必须）：
    - 选项1：`同意合并连续 △（推荐）`——仅对 RISK 集授权，把连续 △ 段合并为 1 条或少量完整 △，完整保留全部事实与表演动作，只减少 △ 条数（不删减内容、不改台词、不改锁行）。
    - 选项2：`不处理，保留全部 △ 原子`。
    记录用户选择；未选择或选择不处理时跳过授权，按原样继续。
11. 读取 `work/preflight/report.json` 的 `episodes`，得到全部集号（两位数 epNN）。
12. 每波最多 20 集，在【同一条消息】并列发出 episode-optimizer task（每个任务一次完成修复、丰富动作与格式标准化）；每个调用：
    - `agent`: `episode-optimizer`
    - `description`: `修复优化 EPnn`
    - `prompt`（基础）：`处理第 NN 集。严格执行 .opencode/agents/episode-optimizer.md：读取 work/meta/paragraphs.txt 中本集段落范围与 work/preflight/report.json 中本集 must_fix/suspected/scene_unify，修复已确认问题、处理疑似问题、适度丰富动作执行，并把本集整理成标准格式；台词与结构行逐字锁定。完整写出 work/preflight/optimized/epNN.md 与 work/preflight/optimized/epNN.json。只回一行状态。`
    - `prompt`（仅当用户选择选项1且本集在 `atom_pacing.json` 的 `risky_eps` 中，则在基础 prompt 后追加）：`本集已被标记为 △ 节奏风险，用户已授权合并连续 △：按 .opencode/agents/episode-optimizer.md 的「C. 连续 △ 合并（内容保真）」执行——把连续 △ 段合并为 1 条或少量完整 △，完整保留全部事实与表演动作，只减少 △ 条数（不删减内容、不改台词、不改锁行）；并在 epNN.json 的 items 中逐条记录 type=atom_merge。`
13. 每波完成后检查 `work/preflight/optimized/epNN.md` 与 `epNN.json` 是否齐全；缺失或失败的重发一次（重试任务先读原失败原因）；仍失败则报告并停止，不得跳过。
14. 全部集完成后，抽查确认每集 `epNN.json` 记录了修复与丰富项（以及授权集是否记录了 atom_merge）。

## 阶段 3：应用回写与直接存档（脚本，0 token）

15. 运行 `python tools/assemble_source.py`：校验优化产物 → 回写源 docx（原 docx 备份到 `work/preflight/original/`，记录 `optimization_manifest.json`）→ 由优化产物直接合并生成 `work/source/epNN.md` 存档，并生成 `work/meta/` 的 `ep_index.json`、`handoff.json`、`facts_lock.md`、`progress.json`、`format.json`、`format_rules.md`。失败则报告并停止（源 docx 被占用时提示关闭 Word/WPS 后重跑）。
16. 运行 `python tools/verify_optimized.py` 做台词锁定校验（比对源段落与 work/source 存档的台词行）。如有 FAIL 集，把失败详情输出到会话并写入最终报告，提示需人工复核。

## 阶段 4：全剧分析（单次 task）

17. 发一个 task 调用 story-analyst：
    - `agent`: `story-analyst`
    - `description`: `全剧分析`
    - `prompt`: `完整执行 .opencode/agents/story-analyst.md，读取 work/meta/ep_index.json、work/meta/facts_lock.md、work/source/ep*.md 与 work/preflight/report.json，归纳全剧核心主线、全剧梗概、核心卖点、人物动机与性格、核心驱动、类型与情绪基调、待确认风险，写出 output/<stem>_全剧分析.md。只回一行状态。`
18. 确认 `output/<stem>_全剧分析.md` 已生成；缺失则重试一次；仍失败则报告用户但不阻断后续汇总。确认后运行 `python tools/analysis_build_docx.py`，生成 `output/<stem>_全剧分析.docx`；失败只报告，不阻断汇总。

## 阶段 5：汇总

19. 输出最终汇总：
    - 输入文件与集数；前置评级与 must_fix / suspected 数量
    - 词数检测结论（不合格集列表）
    - △ 节奏检查结论（风险集列表 + 用户是否授权合并连续 △，及处理结果）
    - 对白密集/动作不足结论（风险集列表，仅报告、不补写）
    - 优化存档路径：`work/source/epNN.md`（共 N 集）；源 docx 备份路径（`work/preflight/original/`）
    - 台词锁定校验结果
    - 全剧分析路径：`output/<stem>_全剧分析.md` / `.docx`
    - 下一步提示：运行 `/炼剧本` 进行并发炼本，或 `/配乐` 生成配乐提示词
20. 结束。不要运行炼本、不要调用 director。

约束：不要把剧本正文读进主上下文；不要修改 `参考资料/`；worker 只回一行状态；全剧分析正文不要读进主上下文；每波 task 调用必须在同一条消息并列发出以保证并发。△ 节奏检查为信息项，不得因它阻断流程或自动修改正文；仅在用户明确同意后才授权合并连续 △。
