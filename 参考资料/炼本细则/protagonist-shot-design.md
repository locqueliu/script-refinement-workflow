# 主角镜头贯穿与镜头规划 | PROTAGONIST SHOT THROUGHLINE

> 适用：已通过前置主角覆盖检查、进入炼本的集。
> 主角来源：`work/meta/protagonist.json`（自动识别，单主角，不做双主角）。
> 配置：根目录 `shot-profile.json`。

## 一、核心原则

1. 先做镜头规划，再写正文。
2. 每个镜头必须有明确的主体（PRIMARY）和镜头功能。
3. 大多数镜头必须与主角产生视觉、视线、因果或声音关联。
4. 不得为了比例把主角塞进画面当背景。
5. 不得新增 SOURCE 未建立的主角在场、能力、关系、道具或事件。
6. 本规则只处理已进入炼本的集；整集无主角/主角戏份极少由前置质检拦截，不在本规则内处理。

## 二、三类镜头

| 类型 | 定义 | 是否计入主角关联 |
|---|---|---|
| **P｜主角镜** | 镜头主体就是主角：脸、眼、身体、动作、决定、POV、手部插入、主角反应 | 是 |
| **R｜主角关系镜** | 主体是配角/环境/道具，但通过合法关系锚定到主角 | 是 |
| **N｜非主角镜** | 与主角没有视觉/视线/因果/声音关联 | 否 |

### R 的合法子类型

| 子类型 | 锚点 | 例子 |
|---|---|---|
| `pov` | 主角主观视点 | 主角看向门口，切门口的人 |
| `ots` | 过肩/前景带主角 | 主角肩后拍对面配角 |
| `foreground` | 主角在前景（虚焦/局部） | 主角侧脸虚焦在前景，焦点在配角 |
| `frame` | 主角通过门框/窗框/缝隙观察 | 门缝里主角的眼睛，画外是配角 |
| `observe` | 主角在画内观察，且观察本身是叙事 | 主角在车窗外看着，焦点在远处 |
| `object` | 主角的手/物件进入画面并承担信息 | 主角指节压在柜台上；主角手里的照片 |
| `hand` | 主角手部细节 | 主角手指收紧、松开、敲击 |
| `voice` | 主角 VO/OS 覆盖画面 | 主角旁白覆盖配角画面 |
| `reaction` | 配角动作/台词落在主角反应上 | 配角说完，切主角下颌绷紧 |
| `cause` | 配角镜头是主角上一动作的直接结果 | 主角推门 → 配角回头 |
| `sound` | 主角画外声音触发画面 | 主角脚步/呼吸/敲击先入，下一镜揭示主角 |
| `reflection` | 主角倒影/反光 | 玻璃里主角的倒影 |
| `shadow` | 主角影子入画 | 主角影子先落在墙上 |

## 三、比例指标

默认值见 `shot-profile.json`，初始建议：

| 指标 | 硬底线 | 目标 |
|---|---:|---:|
| `(P+R)/total` 主角关联镜占比 | ≥ 70% | 80%—85% |
| `P/total` 主角本人镜占比 | ≥ 35% | 40% |
| `N/total` 非主角镜占比 | ≤ 30% | ≤ 20% |
| 连续 N 镜 | ≤ 2 | ≤ 1 |
| 连续配角互动 N 镜 | ≤ 2 | ≤ 1 |
| 有主角在场场次的主角关联镜 | ≥ 1 | ≥ 2 |
| 主角特写占全部特写 | ≥ 30% | 40% |
| 关联点类型数 | ≥ 3 | ≥ 4 |
| `R-OBSERVE` 占关联镜 | ≤ 30% | ≤ 20% |

> `shot-profile.json` 的 `mode` 为 `warn` 时只报告；改为 `enforce` 后硬指标阻断。

## 四、规划步骤（先规划后写）

1. **读主角**：读 `work/meta/protagonist.json`，确认唯一主角与别名。
2. **读场次地图**：读 `work/preflight/protagonist.json` 中本集 `scene_map`，确认每场主角是否在场。
3. **写每场贯穿线**：主角这场要什么 → 遇到什么阻碍 → 做了什么决定 → 状态变成什么。
4. **先排 P 镜**：首次揭示、决定、动作结果、情绪落点优先给主角本人。
5. **再排 R 镜**：配角互动段选合法锚点；每个配角互动段至少一个 R。
6. **最后排 N 镜**：环境、奇观、纯配角段；连续不超过 2 镜，并尽快切回 P/R。
7. **自检比例**：不达标先改规划，不要靠正文硬塞。
8. **按规划写正文**：每个镜头块在 `【人物站位】` 或 `△` 中落下对应关联点。
9. **写报告**：把 `shots` 与 `stats` 写入 `work/report/epNN.json` 的 `shot_plan`。

## 五、场次级规则

- `scene_map` 中 `has_protagonist=true` 的场次：至少 1 个 P 或 R；没有即失败。
- `has_protagonist=false` 的场次：允许 N；计入全集 N 比例和连续段；不新增主角，不写例外字段。
- 每个配角互动段（连续以配角为主体、且不是 R 的镜头）不超过 2 镜；第 3 镜前必须切回 P/R。

## 六、合法关联手段

- 主角 POV：切到主角看到的东西；主角可以不在画面内。
- 过肩/前景：主角肩、手、侧脸在前景，焦点在配角。
- 反应切：配角情绪落点切主角的脸、手、呼吸、下颌。
- 手部/物件插入：主角的手、指节、手机、照片、武器、杯子进入画面。
- 框内观察：门框、窗框、帘缝、车窗外，主角在画内看着。
- VO/OS：主角画外音覆盖配角画面；主角若在画内，嘴巴保持闭合。
- 因果回切：配角动作是主角上一动作的直接结果。
- 声音桥：主角画外脚步/呼吸/敲击触发配角镜头，下一镜揭示主角。

## 七、禁止手段

- 在 SOURCE 没有主角在场的场次硬加主角。
- 主角站在背景里，没有动作、决定、反应（主角墙纸）。
- 为塞主角破坏 180 度轴线、空间关系、站位连续性。
- 把配角变成纯反应道具；配角仍要有自己的 ACTION / RECEIVE / HANDOFF。
- 因为台词里提到主角名字，就把镜头标成 R。
- 每个配角镜都用同一种过肩；关联点必须有变化。
- 每句台词都切主角特写；镜头跟情绪节拍，不机械交替。
- 为比例牺牲 SPECTACLE、建立镜或动作过程。

## 八、场景类型 playbook

| 场景类型 | 规划策略 |
|---|---|
| 主角独处 | P 为主；环境镜用 POV / 手部插入 / 主角观察 |
| 双人对白（主角+配角） | 正反打；配角说话连续不超过 2 镜；情绪落点切主角反应；过肩/前景做关系 |
| 配角对白（主角在场） | 主角作为观察者/被谈论者；用 OTS、前景、反应切、手部插入；每 2 镜回主角 |
| 群像/多人 | 主角是视觉锚点；前景/背景分层、焦点转移、视线关系 |
| 动作/奇观 | 主角在因果链里（做、承受、反应）；纯奇观 N 镜不超过 2，切回主角反应/决定 |
| 反派独场 | 用主角 POV/监听/事后发现；若 SOURCE 无主角，按 N 计入比例，不硬加 |
| 过渡/蒙太奇 | 主角 VO/OS、主角物件、主角移动方向；否则 N，但受连续段限制 |

## 九、示例

SOURCE：

```text
1-1 夜 内 当铺
人物：林砚 掌柜 打手
△ 林砚推门进入，停在柜台前。
掌柜（对白）：东西带来了吗？
△ 打手从帘后走出，堵住门口。
林砚（对白）：先让我看看货。
```

合格规划：

```text
S01 林砚推门进入，停在柜台前          P / action
S02 过肩：林砚前景肩后，掌柜在柜台后   R / ots
S03 林砚视线方向，帘后打手走出         R / pov
S04 林砚手按柜台，指节收紧             P / hand
S05 掌柜看货，林砚在画左前景虚焦       R / foreground
S06 林砚开口，下颌线绷着               P / face
```

## 十、报告结构

写入 `work/report/epNN.json`：

```json
{
  "ep": 1,
  "status": "OK",
  "protagonist": "林砚",
  "shot_plan": {
    "shots": [
      {"no": 1, "scene": "1-1", "subject": "林砚", "subject_type": "protagonist", "relation": "P", "anchor": "action", "purpose": "建立主角与当铺空间"},
      {"no": 2, "scene": "1-1", "subject": "掌柜", "subject_type": "support", "relation": "R", "anchor": "ots", "purpose": "掌柜的问话落在林砚判断上"},
      {"no": 3, "scene": "1-1", "subject": "打手", "subject_type": "support", "relation": "R", "anchor": "pov", "purpose": "林砚注意到门口被堵"}
    ],
    "stats": {
      "total": 3,
      "p": 1,
      "r": 2,
      "n": 0,
      "related_ratio": 1.0,
      "protagonist_ratio": 0.333,
      "n_ratio": 0.0,
      "max_n_run": 0,
      "max_support_run": 0,
      "scene_missing": [],
      "closeup_share": 0.0,
      "anchor_variety": 2
    }
  }
}
```

字段约束：

- `relation`：`P` / `R` / `N`。
- `subject_type`：`protagonist` / `support` / `environment` / `prop` / `spectacle`。
- `anchor`：P 使用 `face/eyes/body/action/hand/pov/voice/reaction/decision`；R 使用 `pov/ots/foreground/frame/observe/object/hand/voice/reaction/cause/sound/reflection/shadow`；N 使用 `none`。
- `no` 必须从 1 连续递增，且与正文镜头块顺序一致。
- `shots` 数量必须等于正文镜头块数量。

## 十一、自检

- 主角关联镜是否 ≥70%？主角本人镜是否 ≥35%？纯 N 是否 ≤30%？
- 是否有连续 3 个以上 N 镜？是否有连续 3 个以上配角互动 N 镜？
- 有主角在场的场次是否都有至少 1 个 P/R？
- 是否有"主角站在背景里"的墙纸镜头？
- 关联点是否至少有 3 种？`observe` 是否过多？
- 是否新增了 SOURCE 没有的主角在场、能力、关系或事件？
- 删除所有镜头块后，SOURCE 事实与台词是否仍完整？
